also watch the redaction screen catch them. Server limit: 10 audits per account per day.

## The consolidated EOB — for the EOB library / batch sharing

**`t-eob.pdf` is ONE statement covering the t1, t2, and t3 claims.** Use it *instead of*
`t1/t2/t3-eob.pdf`, never alongside them:

- Single audit: `t1-bill.pdf` + `t-eob.pdf`, leave "save this EOB" checked.
- Reuse: then audit `t2-bill.pdf` alone — the saved EOB is pre-selected.
- Batch: drop `t1-bill.pdf` + `t2-bill.pdf` + `t3-bill.pdf` + `t-eob.pdf` in one go →
  3 audits, all sharing the consolidated EOB.

It does NOT cover t4–t6 or p1 — auditing those against it should flag `not_in_eob`.

Answer key for scripted checks: `series-expected.json`. Regenerate HTML fixtures with
`node gen-series.mjs` (PDFs are rendered from the HTML via the browse CLI).

## Family (`family/`) — two live defects, reproducible

Generated by `node gen-family.mjs`. Uses the column vocabulary from the real CMS
sample EOB in `real-eob/`, and the same $500 individual / $1,000 family
deductible as the real SBCs in `real-sbc/`, so all three sets compose.

| Upload together | What should happen |
|---|---|
| `matthew-bill` + `family-eob` | flu shot 90686, $85 billed / $32 allowed, nothing owed |
| `sarah-bill` + `family-eob` | the same, for a different person on the same day |
| `emma-bill` + `family-eob` | 99213 billed **twice** on one statement — a genuine duplicate |

**Family duplicate.** Matthew and Sarah were both seen at the same clinic on the
same day for the same code. Two people, two legitimate charges. Before
`patientName` existed, `crossBillDuplicates` keyed on provider|code|date alone
and reported the second as "a provider billing you twice" — telling a user to
dispute a charge they owe. Emma's bill is the control: a real duplicate that
must keep firing.

**Family deductible.** `family-eob` states $640 of the $1,000 FAMILY deductible.
`deductibleTarget` used to read `.individual` unconditionally, rendering 128% of
a limit the household was 64% through, and flagging the EOB's correct family
figure as a conflict with the plan.

## Real documents (`real-sbc/`, `real-eob/`)

Genuine CMS and DOL publications — see `real-sbc/README.md`. The SBC format is
ACA-mandated and standardized, so those samples are structurally what a member
uploads. There is no equivalent for EOBs: they are payer-specific and full of
PHI, so nobody publishes a corpus, and `real-eob/cms-sample-eob.pdf` is an
annotated teaching document rather than a clean statement. That is why the
family EOB above is synthesized.

## Older SBC — for the replace-with-an-older-plan confirmation

`fake-sbc-older.html` is `fake-sbc.html` with the coverage period shifted to
01/01/2025 – 12/31/2025. Upload it via **Replace** on the plan card while the 2026 plan is on
file and the app asks "Replace the plan on file with an older one?" — the one confirmation in
the app that is deliberately NOT red, because replacing a plan destroys nothing (X1 step 5).
The SBC input accepts `text/html`, so this needs no PDF render.
